# Canvas Pilot 0.10.0-rc.1

First release candidate for the 0.10 minor release. This local annotated source
tag collects development through v0.9.76; it is not a published binary release.

## Highlights

- Shared device input editing with protected categories, explicit sends, crop
  handles, pivot zoom and live capture composited into the applied crop region.
- Improved input editor layout, highlighted pending sends and view navigation
  while crop editing is locked.
- Correct Midra cropped-capture proportions throughout layer previews and helpers.
- Local layer reference pictures for offline cropping, plus expanded document
  reference import and software-integration discovery.
- Device-change conflict handling and opt-in input switching on Send.
- Separate internal load/send mappings, while the current GUI keeps them synchronized.

The [changelog](../../canvas-pilot/changelog.md) records individual changes.

## Compatibility and limits

Project schema 20 retires local input pre-crop settings and input proposals in
favor of shared device Input settings. Best-effort loading reports skipped or
reset data and opens repaired documents as unsaved copies; unknown versions and
unusable documents remain errors. Keep originals when evaluating this candidate.

Independent mapping controls and multiple project screens are still future work.
Aquilon framing transfers with active shared crop/aspect correction retain their
existing restrictions. This candidate does not add switcher adapters.

## Validation

The implementation at v0.9.76 passed formatting, both Clippy configurations,
default/all-features/no-proprietary workspace tests, rustdoc, the manual build
and the coverage gate (91.41%). The candidate changes only version metadata and
release documentation; Cargo metadata, formatting and the manual build are
checked again for this checkpoint.

No candidate release bundles or platform runtime acceptance have been performed.
The latest preview-aspect correction has automated rendering coverage, but has
not been checked against live device output. Earlier device observations remain
documented evidence, not a new hardware acceptance claim.
