# Canvas Pilot v0.10.0-rc.18

This release candidate improves precision work at high canvas zoom while removing
a performance regression that could eventually make the editor unresponsive.

- Extreme scroll zoom no longer asks egui to rasterize decorative canvas labels
  thousands of pixels tall. Those labels hide above a safe raster size while
  layers, handles, fixed-size labels, pixel guides and the full 256× camera range
  remain available. This also prevents the shared font atlas from corrupting
  ordinary interface text or slowing the application.
- With snapping and **Pixel edges** enabled, movement, resize handles and pivots
  now prefer whole output pixels within a quarter-pixel magnetic zone. Moving
  farther away preserves the exact fractional coordinate. Screen, layer, grid and
  mirrored-contact snaps retain priority, and explicit 10/100 px grids stay exact.
- Yanked transitive lockfile entries were refreshed to compatible patch releases,
  removing their warnings from local Cargo installation and release builds.

Use a portable bundle for the application, icons and launcher helper. Canonical
`.tgz` archives are available for cargo-binstall; raw binaries are also provided.
The separate `classic-themes.zip` and `video-game-themes.zip` assets install the
17 distributed example themes in two bounded collections. `language-pack.zip` is
the format-2, revision-1 Ukrainian/Bhojpuri teaching example; those translations
remain partial and unreviewed. Theme notices are included in each theme pack, and
game-inspired palettes contain no game assets.

Project schema 20 and settings schema 15 are unchanged. Existing projects and
preferences remain compatible; the pixel preference uses the existing snapping
option and does not add persistent fields.

Formatting, both Clippy configurations, all required Rust test configurations,
rustdoc, all 33 Python checks, the pinned manual build, theme-pack byte validation
and the coverage gate passed. Whole-application line coverage is 91.69%. No device
writes were performed. Cross compilation and package validation do not replace
native Windows or macOS runtime acceptance.
