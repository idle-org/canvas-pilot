# Canvas Pilot v0.8.0 — Standalone and advanced exchange milestone

Canvas Pilot is now an independent application and repository, with its own book,
build pipeline and release packaging. This milestone brings the editor, device
adapters and exchange workflows together for release preparation.

## Highlights

- Midra and Aquilon adapters with reviewed transfers, partial updates and saved
  device mappings. Device-specific behavior stays behind the adapter interface.
- Advanced layer fit, visual crop movement, blanking masks and opt-in input
  correction proposals, while keeping the normal crop workflow straightforward.
- Eleven exchange formats, starter templates, compatibility tiers and separate
  basic/advanced feature matrices. Supported export snapshots preserve wider
  editable state; saved device correction proposals restore inactive.
- Exact Canvas Pilot clipboard geometry, crop edges/offsets, all fit modes and
  blanking, with independent paste options and atomic undo.
- Optional destination renaming from supplied editor names. Name-only imports
  preserve folders, layer identity and device links; unnamed items stay unchanged.
- A consolidated illustrated manual, installation guidance, downloadable templates
  and a development roadmap separate from the user guide.

## Compatibility

Native projects use the suggested `.pilot.json` extension; Open project validates
any `.json` filename. Existing supported project versions migrate through the
normal loader. Project schema 16 preserves device links and inactive proposals.
A native project is a Canvas Pilot format, not an industry interchange standard.

Clipboard payload version 2 stores actual layer names. This version reads v1
geometry/appearance and legacy normal-crop text; v1 names are display labels and
are not used for renaming. Older clipboard readers reject v2 explicitly.
Crop & fit paste requires matching effective source dimensions. Renaming starts
disabled and uses only names supplied by the source format.

Default builds include vendor codecs. Illustrator files require the external
VectorCraft converter. Builds using `no_proprietary` exclude optional vendor codecs;
release builds should keep the default features.

## Validation and release status

The feature baseline passed default, all-feature and restricted-build tests,
Clippy with warnings denied, formatting, rustdoc, and manual link/anchor checks.
Whole-application line coverage at the feature milestone is **91.09%**. Name
round trips cover all available codecs except native Illustrator conversion,
which requires VectorCraft. SVG text naming is tested separately.

This is a source milestone and release candidate for packaging, not a claim that
platform binaries have been built or smoke-tested. Before public binary release:

- Build and package Windows x86-64, Linux x86-64, Apple Silicon and Intel macOS
  using the pinned release configuration on a capable build host.
- Check archive contents and application startup on the target platforms.
- Verify the published canonical archives with cargo-binstall.

Emulator/readback evidence does not replace physical-output acceptance. Remaining
precision questions and acceptance work stay in the [project plan](https://proxy.dandaedre.com/gitea/idle-org/canvas-pilot/src/tag/v0.8.0/docs/canvas-pilot/plan.md).
